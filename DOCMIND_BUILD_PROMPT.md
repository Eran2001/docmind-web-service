# DocMind — Build Prompts (for Claude Sonnet 5.5 in Copilot Agent mode)

## How to use this file

1. Put these in the repo root:
   - `docs/01-docmind-rag-platform.md` (the spec)
   - `docs/design/*.html` (the 10 extracted design screens, NOT the original bundled `DocMind.html`, which is compressed and unreadable to the model)
   - `.github/copilot-instructions.md` → paste **Part A** into it (Copilot loads it on every request)
2. Open Copilot Chat → **Agent** mode → **Claude Sonnet 5.5**.
3. Run the prompts in **Part C** one at a time. Start a **new chat per phase**. Don't move on until the phase's "Done when" passes.

## Part A — Paste into `.github/copilot-instructions.md`

```markdown
# DocMind — Project Rules

Source of truth: `docs/01-docmind-rag-platform.md` (the spec). Visual source of truth: `docs/design/*.html`.
If something is in neither, ASK before inventing it.

## Hard rules
- Follow the spec's tech decisions (Section 2) and phases (Section 14). One phase at a time.
- EXCEPTION: the frontend (`apps/web`) uses the stack + folder structure in "Frontend architecture" below. This overrides spec Section 4 for `apps/web` only.
- TypeScript strict. No `any`. Typed Python with Pydantic.
- Python AI service is stateless; only the Node API touches Postgres.
- Error shape everywhere: `{ error: { code, message, details? } }` (spec 8.1).
- No hardcoded secrets. Env validated with zod (Node/web) and pydantic-settings (Python).
- Write tests per spec Section 13 for every phase. Update README.md after each phase.

## Frontend stack (apps/web)
Next.js 15 App Router + TypeScript + Tailwind CSS v4 + shadcn/ui + lucide-react
TanStack Query v5 (server state) · Zustand (client/UI state only) · Axios (JSON requests)
react-hook-form + zod · sonner (toasts) · next-themes (dark mode) · react-markdown · recharts

## Frontend architecture
apps/web/
├── public/                       # static files (favicon, og image, sample files)
├── src/
│   ├── app/                      # ROUTING ONLY. page.tsx/layout.tsx stay thin: import a view and render it.
│   │   ├── layout.tsx            # <html>, fonts, <Providers>
│   │   ├── page.tsx              # landing → views/landing
│   │   ├── not-found.tsx
│   │   ├── (auth)/layout.tsx
│   │   ├── (auth)/login/page.tsx
│   │   ├── (auth)/register/page.tsx
│   │   └── (app)/
│   │       ├── layout.tsx        # AppShell (sidebar + main)
│   │       ├── collections/page.tsx
│   │       ├── collections/[id]/page.tsx
│   │       ├── collections/[id]/chat/[[...conversationId]]/page.tsx
│   │       ├── evals/page.tsx
│   │       ├── evals/[setId]/page.tsx
│   │       ├── usage/page.tsx
│   │       └── admin/usage/page.tsx
│   ├── views/                    # one folder per screen (replaces Vite `pages/`)
│   │   ├── landing/  auth/  collections/  documents/  chat/  evals/  eval-detail/  usage/
│   │   └── <screen>/index.tsx + <screen>/components/*  (screen-private components)
│   ├── components/
│   │   ├── ui/                   # shadcn only — generated by CLI, do not hand-write
│   │   ├── layout/               # AppShell, Sidebar, MobileNav, PageHeader, Breadcrumbs, ThemeToggle
│   │   └── common/               # shared: StatusBadge, EmptyState, ConfirmDialog, DataTable, Skeletons
│   ├── providers/                # Providers.tsx, QueryProvider, ThemeProvider, Toaster
│   ├── configs/                  # env.ts (zod), routes.ts (route builders), query-keys.ts, constants.ts
│   ├── services/                 # Axios calls per domain: auth.service.ts, collections.service.ts, …
│   ├── queries/                  # TanStack hooks per domain: useCollections, useUploadDocument, …
│   ├── stores/                   # Zustand: ui.store.ts (sidebar), citation.store.ts, chat.store.ts
│   ├── schemas/                  # zod form schemas (re-export shared API schemas from packages/shared)
│   ├── hooks/                    # generic hooks: useMediaQuery, useAutoScroll, useDebounce
│   ├── lib/                      # axios.ts (instance + interceptors), sse.ts (stream parser), utils.ts (cn)
│   ├── utils/                    # pure helpers: format-date, format-cost, format-bytes, citations
│   ├── types/                    # frontend-only types
│   ├── assets/                   # imported SVGs/images
│   ├── styles/globals.css        # Tailwind v4 + design tokens
│   └── middleware.ts             # auth redirect
├── tests/ (unit/, e2e/)
├── components.json
└── next.config.ts

## Frontend rules
- NEVER create `src/pages/` — Next.js treats it as the Pages Router. Screens live in `src/views/`.
- `app/` files are thin. Pages are Server Components that render a view; the view (or its children) adds "use client" only where needed.
- Data flow: component → `queries/` hook → `services/` function → `lib/axios.ts`. Components never call axios directly.
- Server state lives ONLY in TanStack Query. Zustand is for UI state (sidebar open, selected citation, streaming status). Never copy query data into Zustand.
- Query keys come from `configs/query-keys.ts` factories. Mutations invalidate the right keys.
- Routes come from `configs/routes.ts` (e.g. `routes.chat(collectionId, conversationId?)`), never string literals.
- Axios instance: `baseURL = env.NEXT_PUBLIC_API_URL`, `withCredentials: true`. Response interceptor: on 401 call `/auth/refresh` ONCE (share one in-flight promise across concurrent 401s), retry the request; if refresh fails → redirect to `/login`. Normalize errors to the spec error shape.
- SSE chat stream uses `fetch` + `ReadableStream` in `lib/sse.ts` (Axios can't stream in the browser). Same credentials + same refresh-on-401 logic. Event types come from `packages/shared/src/sse-events.ts`.
- Tailwind v4 is CSS-first: NO `tailwind.config.js`. Tokens go in `globals.css` via `@theme inline`. Dark mode via `.dark` class (next-themes `attribute="class"`) with `@custom-variant dark (&:where(.dark, .dark *));`.
- Use shadcn components (install with `pnpm dlx shadcn@latest add <name>`) and restyle them through tokens, not by rewriting them.
- Icons: lucide-react only, same icon names as the design.
- Responsive down to 375px; sidebar becomes a Sheet below 768px.
```

## Tips

- If the model drifts from the design, say: *"Open docs/design/0X-Name.html again and match spacing, copy and states exactly."*
- If a phase chat gets long and slow, start a new chat with: *"Continue Phase N. Here's what's done: … Here's what's left: …"*
- Deploy note: the spec puts web on Vercel and the API elsewhere. Cross-site cookies won't reach `middleware.ts`. Either put both on the same parent domain (`app.` + `api.`) or add a Next.js `rewrites()` proxy from `/api/v1/*` to the API so cookies are first-party. Decide this before Phase 2 and tell the model which one.
- If you scaffold with the latest Next.js instead of 15: in Next 16 `middleware.ts` is renamed `proxy.ts`. Tell the model which version you're on.
